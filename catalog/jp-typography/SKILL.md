# 和文タイポグラフィ規約スキル（jp-typography）

あなたは、**和文サイトの組版が崩れない状態を最初から作る**担当です。

このスキルは**予防**を担当します。「生成時に守れば発生しない」規約を初期構成に入れ、
描画して測らなくても大半の改行事故が起きない状態にします。

> ## ⚡ 最重要の原則
>
> **修正より生成時に守るほうが安い。** 実案件では、本スキルの規約を守っていれば
> 25 往復の指摘のうち 9 割が発生しませんでした。
>
> 新規構築なら、まず `references/rules.md` を読んで初期構成に織り込むこと。
> 後付けは高くつきます（データ全体を通し直し、構造化データへの混入を全ページ検証することになる）。

## 扱う範囲

**扱う**: 生成時に守る組版規約、改行事故を防ぐ実装レシピ、枠に入る文の書き方。

**扱わない**: 実描画の計測・走査による検出、ブラウザ実測での採点。本スキルは
ヘッドレスブラウザを前提にしません。予防で潰しきれなかった箇所は、
規約 A〜C の適用漏れを疑って初期構成を見直します。

## 最初に打つ手：`word-break: auto-phrase`

個別の箇所を直しにいく前に、**まずこれを 1 行入れる**。文節境界を優先して折り返すため、
「行頭に助詞が落ちる」と「最終行の孤立」の大半が消えます。
**文言もマークアップも変えずに済む**のが効きます。

```css
p, li, dd, dt, figcaption { word-break: auto-phrase; }
line-break: strict;   /* 長音符・小書き仮名の行頭落ちを防ぐ。別問題なので併用する */
```

7 ページ規模のサイトでの実測:

| 指標 | 幅 | 適用前 | 適用後 |
|---|---|---|---|
| 行頭に助詞 | 414px | 24件 | **5件** |
| 行頭に助詞 | 360px | 44件 | **4件** |
| 最終行4字以下 | 414px | 9件 | **0件** |
| 最終行4字以下 | 360px | 10件 | **2件** |
| 最終行4字以下 | 768px | 2件 | **0件** |

いずれの幅でも横スクロールは発生しませんでした。

**残るもの**: 「〜により」「〜によって」「〜による」など、複合辞・補助動詞を別文節として
扱う箇所。数が少ないので `.nb`（`white-space: nowrap`）で個別に包みます。

**ただし `auto-phrase` は Chromium 限定**です。次項の BudouX と必ずセットで入れます。

## 全ブラウザに広げる：BudouX

`auto-phrase` は **iOS Safari が最新版でも未対応**（2026-08-12 時点で iOS Safari 3.2〜26.5 /
Firefox 2〜156 がいずれも未対応）。和文サイトはモバイル比率が高くその大半が iOS Safari なので、
`auto-phrase` だけでは**訪問者の一部にしか効いていない**状態になります。

BudouX でビルド時に文節境界へ `<wbr>` を置き、`word-break: keep-all` と組み合わせます。
手順・落とし穴は `references/fix-patterns.md` の `0.4`。

- **ビルド時のみ**。モデル 20.5KB もクライアント JS も成果物に載せない
- `translateHTMLString()` は使わない（ZWSP U+200B が混入する）。`parse()` + 自前 `<wbr>`
- `<wbr>` を構造化データ・`title`・`meta`・`alt`・`llms.txt` に入れない

## 規約 A〜D（正本: `references/rules.md`）

| 節 | 内容 |
|---|---|
| **A. 割ってはいけない語** | 英字複合語（生成AI / Webシステム）は `whitespace-nowrap`、中黒でつないだ一語（設計・開発）は WORD JOINER `U+2060`。**「一語」か「列挙」かは意味で判断する**（機械的には区別できない）。列挙の中黒は行末に置くのが正しい組版 |
| **B. 改行と行数** | 和文を要素内で改行しない（ソースの改行は半角スペースになる）。改行位置はデータ側に `"\n"` で持ち表示時に `<br>` へ変換する（`WrapText` 方式）。`text-wrap: balance` は使わない。本文は `text-sm md:text-base` |
| **C. レイアウト** | 多列化は `lg` 以降（`md:grid-cols-4` は 768px で 1 枚 101〜200px になりモバイルより狭い）。カード余白は `p-6 sm:p-8`。項目リストは `w-fit` |
| **D. 文章の書き方** | FAQ の回答は「1行目＝直接の答え」（AI 検索が答えを抜き出しやすい構造でもある）。枠に入れる文は生成時に文字数上限を設ける（目安: カード本文 1 行 18 字・全 5 行）。同一カード群で常体の体言止めと敬体を混在させない |

## 実装レシピ（正本: `references/fix-patterns.md`）

手法 0〜7 を収録: `auto-phrase` / BudouX / `WrapText` / `.jp-fixed-lines` /
`whitespace-nowrap` / WORD JOINER / 和文中の半角スペース除去 / レイアウト側の対処。

## 禁止事項

1. **`text-wrap: balance` で改行位置を制御する**（行長を揃えるだけ。実測で 375px の見出しが「システム開」/「発・リース」と語中で割れた）
2. **`word-break: auto-phrase` だけで完了とする**（Chromium 限定。iOS Safari には 1 件も効いていない）
3. **`word-break: keep-all` を当てて `<wbr>` も `overflow-wrap` も置かない**（和文が 1 文字も折り返せず、行が崩れるのではなく枠からはみ出す）
4. **データに `<br>` を直接書く**（構造化データ・`alt`・`meta` にタグが混ざる）
5. **和文テキストを要素内で改行する**（半角スペースとして出力される）
6. **指摘された 1 箇所だけを直す**（同じ症状は他ページにもある。症状の性質は最初の 1 件で分かるので、その時点で全ページ分を一括で直す）
7. **`md:grid-cols-3` / `md:grid-cols-4` で多列化する**（768px で 1 枚がモバイルより狭くなる）
